## T-701 Return to an earlier stage, impact analysis, stale marking

**Goal:** send an approved run back to an earlier stage, work out at object level what the change affects, mark exactly that as stale, block everything built on stale artifacts, and regenerate only what is stale.

**Steps taken**
1. **Stale model** (`app/workflow/stale.py`): `StaleArtifacts` exception (`409 STALE_ARTIFACTS`, `details.stale`) and `assert_fresh(run, names)`. Artifacts get `ArtifactRef.status = "stale"`.
2. **State machine** (`states.py`, `run.py`): `MODEL_APPROVED` and `REPORT_APPROVED` gained a transition to `DATA_PROFILED`. `apply_transition` refuses `DEPLOYING` while anything is stale, and checks that before legality.
3. **Return log** (`app/workflow/returns.py`): `runs/<id>/returns.jsonl`, one event per line (`returned`, later `resolved`). A `returned` event holds a baseline of every artifact (hash and, where it matters, the parsed content). Helper `reopened_after` counts approvals by their order in `approvals.jsonl`, not by timestamp (timestamps have second resolution and gave wrong answers).
4. **Return** (`app/workflow/impact.py:return_run`, `POST /runs/{id}/return`, body `{"to": "REQUIREMENT_ANALYSIS"|"PLANNING"|"MODEL", "reason"}`): checks the state against the allowed table (to `CREATED` from `REQUIREMENT_APPROVED`, `DATA_PROFILED`, `PLAN_APPROVED`, `MODEL_APPROVED`, `REPORT_APPROVED` or a `NEEDS_INPUT` that waited after real progress; to `DATA_PROFILED` from `PLAN_APPROVED`, `MODEL_APPROVED`, `REPORT_APPROVED`; to `PLAN_APPROVED` from `MODEL_APPROVED`, `REPORT_APPROVED`; anything else, `DEPLOYING` and `COMPLETED` included, is `409 WRONG_STATE` and changes nothing), unlocks the artifact of that stage (the contract becomes a new `draft` version, the plan and ModelSpec or the TMDL model go back to `draft`), writes the baseline, makes the transition. Nothing is deleted.
5. **Impact** (`impact.py:read_impact`, `GET /runs/{id}/impact`, idempotent): empty without an open return. Once the changed artifact is approved again (`approval.perform` calls `impact.on_accept` after every Accept) it compares the baseline with the current files at object level: KPIs by name (`formula_intent`, `grain`, `filters`, `time_logic`, `exclusions`, `currency`, `expected_examples`; wording like the objective changes nothing), entities, dimensions, security, and for the ModelSpec its measures, tables, relationships, roles and storage mode. It applies the dependency map: a changed KPI is stale in `SourceResolution`, `Feasibility` and `ExecutionPlan` (`kpi:<name>`) and in `ModelSpec` through its measure, plus every measure whose DAX uses a changed measure; the TMDL model lists those measures and their table files (`file:definition/tables/<Table>.tmdl`, `definition/relationships.tmdl`, `definition/roles/`); the ReportPlan and the report list the visuals that bind a changed measure or a column of a changed table. A different entity, a storage-mode change, an unreadable baseline file or plan makes the artifacts stale as a whole (`*`). A deleted KPI goes in `removals`, never dropped silently. Artifacts rebuilt since the baseline (different hash) are not stale. The earlier status is kept in `Impact.json` (`prior_status`, `fresh`).
6. **Guards**: stage services call `assert_fresh` for what they build on (plan generation, feasibility, plan edits and Accept of the plan, model generation and Accept, report planning and generation and Accept).
7. **Scope guard** (`app/workflow/scope_guard.py`, option `expect_only`): compares a new folder with the version in place and refuses (`409 SCOPE_VIOLATION`, new error code in `errors.py`) any changed file outside the impact set.
8. **Regeneration** (`app/workflow/regenerate_stale.py`, `POST /runs/{id}/regenerate-stale`): one stage per call, stops where a person must approve. `REQUIREMENT_APPROVED`: G2 again on the unchanged inventory, move to `DATA_PROFILED`. `DATA_PROFILED`: `resolve_sources(restrict=…)`, `check_feasibility(restrict=…)`, `generate_plan(merge=…)` (keeps everything but the changed KPIs' measures), G3 next. `PLAN_APPROVED`: `generate_model`, `add_measures(only=…)`, `write_model_version(expect_only=…)`, then G4. `MODEL_APPROVED`: ReportPlan checked and repointed (a plan that no longer fits is `needs_review`), `generate_report(expect_only=…)`, G5. With nothing stale it walks the run back up through legal transitions and writes a `resolved` event. A measure that gets no DAX is a data gap.
9. **Review reset**: model and report approvals given before a return no longer count (both `role_statuses` use `reopened_after`), so the reviews are required again even if the regenerated files are identical.
10. **Wiring**: the stage files (`source_stage`, `feasibility_stage`, `plan_stage`, `model_stage`, `measure_stage`, `report_stage`, `report_plan_stage`, `plan_review`, `model_review`, `report_review`), `approval.py` (`perform` is a wrapper over `_perform` plus `on_accept`), `api/runs.py`, `schemas.py`, `errors.py`, `cli.py`.
11. **Offline script** `app/manual_tests/t701_offline_checks.py`; docs in `CLAUDE.md`, `CONTRACTS.md`, `MANUAL_TESTING.md`.

**Not built:** a Rayfin screen for the return and the impact.

## T-702 Promotion deployment

**Goal:** after the final release approval, deploy the approved model and report to a target workspace with gates, a lock, a backup, smoke tests and automatic rollback.

**Steps taken**
1. **Client** (`app/deploy/fabric_items.py`): added `get_definition`, `update_definition`, `delete_item` to `FabricItemsClient`. The sandbox guard stays in the client.
2. **The only bypass** (`app/api/deps.py:get_promotion_items_client`): builds the client with `allow_any_workspace=True`, acting as the user (OBO). No other code may do that.
3. **Release approval** (`approval.py` routes to `workflow/promotion.py:decide_release`, artifact `Release`, `POST /runs/{id}/approvals`): role `release_approver` (`403`), state `REPORT_APPROVED` (`409 WRONG_STATE`), nothing stale (`409 STALE_ARTIFACTS`), `expected_hash` current (`409 STALE_VERSION`; the hash is computed from the approved `TMDLModel` and `PbirReport` hashes together), a second approval of the same hash `409 ALREADY_APPROVED`, any other action `422`. An approval given before the last return does not count.
4. **Start** (`promotion.py:start_deployment`, `POST /runs/{id}/deploy`, body `{"target_workspace_id": GUID}`, `202 {"deployment_id"}`): allowed in `REPORT_APPROVED` and `ROLLED_BACK`. Runs **Gate G6** first (saved as `gates/G6-<ts>.json`, `409 GATE_FAILED` lists the failures): G6.1 target isn't the sandbox and is in the user's workspace list (an unreadable list fails); G6.2 G1 to G5 on the current hashes including the latest model and report validations; G6.3 no stale artifacts; G6.4 a release approval on the current hashes. Then it hashes the files on disk against the approved artifacts (`409 HASH_MISMATCH`, `details.artifact`), takes the target lock `runs/.locks/<workspace>.lock` (`409 TARGET_BUSY`; a lock older than 2 hours counts as a crash and is replaced), moves the run to `DEPLOYING`. New error codes `HASH_MISMATCH`, `TARGET_BUSY` in `errors.py`.
5. **Background job** (`promotion.py:run_deployment`, a FastAPI background task, never raises, telemetry stage `deploy.run`): backup of the target's existing model and report through `getDefinition` into `runs/<id>/deploy/backup-<ts>/` (`backup.json` plus files); deploy model `Nexora_<run id prefix>` and report `Nexora_<run id prefix>_Report` with the `upsert_*` methods (the report is a copy of the approved folder with `definition.pbir` rebound to the target's model; the approved folder is untouched); smoke tests `SMOKE.REFRESH`, `SMOKE.MEASURE:<name>` (`EVALUATE ROW`, a blank result is a `warning`), `SMOKE.REPORT` (definition can be retrieved).
6. **Outcomes**: success gives `COMPLETED` and `deployment.outcome: completed`. Any failure restores what existed from the backup and deletes what the deployment created (also a half-created item), then `ROLLED_BACK`. A failed rollback is `rollback_failed` and `NEEDS_INPUT` with a history reason that starts with `CRITICAL`. The lock is always released. `RunManifest.deployment` also has `error` and `rollback`.
7. **Bug fixed in this task:** rollback of an existing item crashed because `p["parts"]` was missing in `_backup` (now `entry["parts"] = p["parts"] = …`).
8. **Offline script** `app/manual_tests/t702_offline_checks.py` (fake Fabric client).

## T-703 Audit trail and traceability

**Goal:** a tamper-evident event log per run, and a trace from a report visual back to the prompt.

**Steps taken**
1. **Event log** (`app/workflow/audit.py`): `runs/<id>/events.jsonl`, append-only, one JSON line per event `{seq, at, type, actor, artifact, version, hash, summary, key, prev_event_hash}`. `prev_event_hash` is the hash of the previous line (genesis value is `sha256:` plus 64 zeros), so an edited, removed, reordered or unreadable line breaks the chain from the next event on.
2. **Sync**: `audit.sync` derives events from what the run already keeps: state history (`state`), approvals (`approval`), artifact registrations (`artifact`), gate results (`gate`), validation entries (`validation`), the deployment (`deployment`), returns (`return`). Each event has a `key`; events whose key is already logged are skipped, so nothing is logged twice. `audit.record` (never raises) runs after every approval action, a return, a regeneration and the end of a deployment. Known limit: lines cut off the end of the log cannot be detected.
3. **Audit endpoint** (`api/runs.py`): `GET /runs/{id}/audit?offset=0&limit=200` (limit 1 to 1000, else `422`) returns `{events, total, chain_valid, first_broken_seq}`; an unreadable line is shown as `{seq, summary: "(unreadable line)", unreadable: true}`. GET calls sync too.
4. **Trace** (`app/workflow/trace.py`, `GET /runs/{id}/trace?visual_id=v1`): returns `{visual, measure{name, dax, model_version}, other_measures, kpi{definition, contract_version, approved_by, approved_at}, sources[{table, column, need, role, profile_evidence}], prompt, gaps}`. The visual comes from `ReportPlan.json` (`404` for an unknown visual or a run without a plan); the DAX is read from the deployed TMDL folder; the KPI is taken from the contract version named in the latest `BusinessContract` approval record; sources are the columns `SourceResolution` maps to that KPI, with their profile from `MetadataInventory.json`. A missing version file, model folder, profile or approval record is an explicit entry in `gaps` ("Contract version 2 is missing"), never a silent skip.
5. **Rayfin**: `src/lib/audit.ts` (display rules, with `audit.test.ts`), types in `src/lib/types.ts`, calls in `src/lib/api.ts`, pages `src/app/runs/[id]/audit/page.tsx` (timeline, 200 events a page, red banner naming the first broken event) and `src/app/runs/[id]/trace/[visualId]/page.tsx`, a link on the run page and a Trace link on each visual of the report page.
6. **Offline script** `app/manual_tests/t703_offline_checks.py`. UI checks: `cd rayfin-ui; npm test; npm run typecheck; npm run build`.

## T-704 Observability

**Goal:** `run_id` as the correlation ID across logs, spans and metrics, with LLM token and cost tracking, exportable to Azure Monitor.

**Steps taken**
1. **Package** `app/observability/`: `context.py` (context variables for `run_id` and stage, `bind`), `logs.py` (JSON logging, `redact`), `telemetry.py` (private OpenTelemetry providers, metrics, `configure(span_exporter, metric_reader)` for in-memory test exporters, `shutdown()`), `middleware.py` (request middleware), `http.py` (adds `x-nexora-run-id` to `requests` calls while a run is bound).
2. **Middleware** (`middleware.correlation`, registered in `api/main.py`): binds `run_id` for every call under `/runs/{id}/...`; each non-GET call opens a span `stage.<name>` (`<name>` is the literal lowercase path segments after the id, e.g. `compile`, `model.validate`, `model.bridges.generate`; function `stage_name`). Span attributes: `run_id`, `stage`, `attempt`, `outcome` (`success`, `rejected` for 4xx, `error` for 5xx or exception), `http.status_code`. Reads bind the run for logs but make no span; `/health` has neither.
3. **Graph spans** (`graphs/base.py:run_graph`): a child span `stage.<stage>.node.<node>` per node run, `attempt` counts how often that node ran in the invocation (a retry is 2 or more and counts in `nexora.retries`). Repair stages are named `model.repair` and `report.repair` (`repair/service.py`).
4. **Metrics** (meter `nexora`, tagged with `run_id` and `stage`): `nexora.stage.duration` (ms), `nexora.errors`, `nexora.retries`, `nexora.validation.passed` (1 or 0; recorded in `gates.save_gate_result` as subject `gate:G<n>` and in `validate_stage.register_report`), `nexora.llm.tokens.input`, `nexora.llm.tokens.output`, `nexora.llm.cost` (USD).
5. **LLM accounting** (`llm/structured.py:ask_structured`): every pipeline model call reads `response.usage`, sends `x-nexora-run-id`, calls `telemetry.record_llm`. Cost is `tokens / 1000 × rate` from `config/model_pricing.yaml` (`<deployment>: {input_per_1k, output_per_1k}`; the committed file is `{}`, so no cost is recorded and a warning is logged once until the rates are filled in).
6. **Logs**: JSON lines on stderr `{ts, level, run_id, stage, msg, logger, …}`; prompts, model answers and secrets are never logged, only `redact(text)` = `{len, sha256}`; exceptions are logged by type only. `configure_logging()` runs at API start.
7. **Settings**: `OTEL_EXPORTER=console|azuremonitor` (`azuremonitor` needs `APPLICATIONINSIGHTS_CONNECTION_STRING`); unset means no export and all telemetry calls are no-ops. Telemetry never breaks a run: each function swallows its own failure and warns once per process. `shutdown()` removes the `_nexora_otel` log handlers, otherwise the exit flush fails.
8. **Other edits**: `gates.py`, `validate_stage.py`, `promotion.py` (stage `deploy.run`), `.env.example`, `requirements.txt`. The CLI and manual scripts are not instrumented.
9. **Offline script** `app/manual_tests/t704_offline_checks.py` (in-memory exporters; use the shared `check` from t502 so a failed check aborts).

## T-705 Security hardening

**Goal:** secrets in Key Vault, a guard that stops row data reaching the model, per-run authorization, no external tracing.

**Steps taken**
1. **Secrets** (`app/security/secrets.py`, used by `app/config.py`): with `KEY_VAULT_URL` set, `azure-openai-api-key` and `entra-api-client-secret` are read from Azure Key Vault with `DefaultAzureCredential` and the `.env` values are ignored. An unreachable vault stops the process at import (`ValueError("CONFIG_ERROR: … KEY_VAULT_URL (<host>) …")`, so the API fails to start and `app.tools.smoke` exits 2); a missing required secret names the secret. Messages hold host and secret name, never a value. `refresh_secret` re-reads a rotated secret.
2. **Payload guard** (`app/security/llm_guard.py`, `check_payload(payload)` raises `PayloadRejected(reason)`): rejects a list of 5 or more same-keyed dictionaries whose keys are not in `METADATA_KEYS`, a list of 5 or more lists of plain values, fields named `rows`, `records`, `samples` and similar with content, 10 or more consecutive delimiter-separated lines, and more than 400,000 characters. JSON inside a string (the model's `input`, also after other text) is parsed and checked the same way. Every payload is logged with `payload_chars` and `payload_shape`; a rejected one with its reason, never its content. **A new payload builder that sends another list-of-records shape must add its keys to `METADATA_KEYS`.**
3. **Shared client** (`app/llm/client.py`, `GuardedClient`, rewritten): `responses.create` runs the guard first; on a `401` it re-reads the key from the vault and retries once (no vault, no retry). `PayloadRejected` is mapped to `422 PAYLOAD_REJECTED` in `errors.py`.
4. **Run authorization** (`app/security/run_access.py`, `api/runs.py:authorize_run`, a router-level dependency on every `/runs/{id}/...` route): a user may act on a run if they created it (`created_by` oid or UPN, ignoring case) or Fabric lists the run's scope workspace for them (`api/deps.py:get_workspace_lister`, the user's own workspace list through OBO, called only when they are not the creator); cached 5 minutes by tenant, workspace and user. An unreadable Fabric is a refusal and is not cached. Otherwise `403 FORBIDDEN` (`RunAccessDenied`). `GET /runs` lists only runs the user may open. A run with no `created_by` (made by the CLI) stays open to any signed-in user; an owned run with no scope is the owner's alone.
5. **LangSmith block** (`app/security/startup.py:assert_no_external_tracing`): `LANGSMITH_TRACING` or `LANGCHAIN_TRACING_V2` true raises `ConfigError("CONFIG_ERROR: …")` at API startup (`main.py`) and when the shared client loads.
6. **Other edits**: `config.py`, `.env.example` (`KEY_VAULT_URL`), `requirements.txt` (Azure Key Vault and identity packages).
7. **Offline scripts** `app/manual_tests/t705_offline_checks.py` (runs every real payload builder through the guard; test clocks must be ordered and monotonic for the cache TTL cases) and `app/manual_tests/t705_guard_demo.py`.

## Gotchas learned

- Run Python as `.venv\Scripts\python.exe -m app.manual_tests.<suite>` from the project root. Avoid `python3 -` heredocs in bash on this machine (one hung and was killed); use a script file or the editor tools.
- Approval-after-return ordering must use the order in `approvals.jsonl`, never timestamps (second resolution).
- `ArtifactRef.status` values now include `stale`; code that lists statuses must handle it.
- Windows can refuse a rename for a moment; use `app/fsutil.py:replace_file`.
- Live-only parts (Fabric deployment and rollback, Key Vault, Azure Monitor, Rayfin screens, a second workspace) need a person with access; the offline suites use fakes.
- The Power BI delegated permission `Dataset.ReadWrite.All` (consent) is needed for the OBO calls of validation and smoke tests; the managed identity needs read access to the Key Vault secrets.
