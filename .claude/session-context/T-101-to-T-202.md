**T-101 (`app/store/`):** Added `app/store/artifacts.py` (`ArtifactStore` protocol; `LocalArtifactStore` wraps the same local folder the first build used directly; `OneLakeArtifactStore` talks to OneLake Files through `app/connectors/onelake_files.py`, which gained `create_if_absent` — an `If-None-Match: *` conditional create, used for lock files — and `list_files`) and `app/store/lease.py` (`FileLease`: an exclusive-create lock file, JSON `{owner, token, expires_at}`, takeover past expiry). `FileRunStore` and `SqlRunStore` both gained `lease`/`release` (`SqlRunStore`'s is a conditional `UPDATE` on new `lease_owner`/`lease_expires_at` columns, added to `dbo.nexora_runs` with an `ALTER TABLE … IF COL_LENGTH(...) IS NULL` migration so an existing table upgrades in place). `Run` gained `active_job: ActiveJob | None` (`job_id`, `operation`, `job_instance_id`, `status`, `started_at`, `finished_at`, `error`, `reserved_by` — the last added for T-105 below). `app/store/pull.py` + `app/cli.py`'s new `runs pull RUN_ID [--to DIR]` command copy a run's files out of the artifact store; `_resolved_run_folder` in `cli.py` makes `contract validate`/`plan validate`/`report validate`/`model generate` accept a `runs/<id>` argument under `ARTIFACT_STORE=onelake` by pulling to a temp folder first (and, for `model generate`, pushing the new version back with `copy_tree` afterwards).

**A real concurrency bug was found and fixed here, not just designed around:** the offline stress check (5 threads × 20 `append_line` calls) first failed intermittently in two different ways under real contention on this Windows machine: (1) `FileLease.release()`'s `path.unlink()` could raise `PermissionError` transiently (a virus scanner/indexer briefly holding the just-written file — the same class of issue `app/fsutil.py:replace_file` already works around for renames) and, swallowed by a bare `except OSError: pass`, left a stale-but-not-yet-expired lock blocking every other writer for the **whole lease duration**, not microseconds; (2) a concurrent `os.open(..., O_CREAT|O_EXCL)` could itself raise `PermissionError` (not `FileExistsError`) while another thread's release/takeover unlink was still in flight. Fixed by retrying `release()`'s unlink (same backoff pattern as `replace_file`) and by treating `PermissionError` in `acquire()` exactly like `FileExistsError` (read the current lock and retry/wait, don't propagate). Verified stable across 15 consecutive runs of the stress check afterwards. This matters for anyone touching `app/store/lease.py` later: a bare `except OSError` around a Windows file delete or create in a contested path is not safe to assume succeeds on the first try.

**T-102 (`app/fabric/`), the dispatcher:** `dispatch.py` holds `OPERATIONS`, the one table from `CONTRACTS.md#fabric-operations` (49 entries at the time, every operation defined up to that point in the spec — including ones whose own task, like T-202's `/compile`, was still `Not started`/`Needs Fabric re-test`; `set_store_override`/`store()` use a `contextvars.ContextVar` so the UDF (which has no token) can swap in a `SqlRunStore` built from its own Manage Connections binding for one invocation. `identity.py` and `job.py` are T-105's, described below since they were built together. `fabric/nexora_api/function-app.py` is the real UDF code (`call`, `me`; thin wrappers over `dispatch()`); `deploy_home.py` gained `udf_definition()` to upload it. `fabric/nexora_stage_runner.Notebook/notebook-content.ipynb`'s cell now calls `app.fabric.job.run_job(...)` for anything other than `operation = "smoke"`.

**Platform research done this session, recorded in `fabric-hosting.md`'s platform-limits table (not assumed):** fetched Microsoft's current docs for User Data Functions' Python programming model, service limits, and Job Scheduler/notebook-invocation APIs. ## 3. Working rules that applied to every task (keep following them)

- **The model proposes, deterministic code decides.** In this session the model is used only by the compile graph (T-202). Run states, transitions, scope checks, token validation, the contract rules and the ambiguity rules are code.
- **No silent KPI assumptions; Data Gap instead of fabrication; never send raw rows to the model.** The compile prompt carries only the prompt, subject area, desired outputs, constraints and the previous contract.
- **Only the store writes manifests.** `FileRunStore` and `SqlRunStore` are the only writers of the run manifest. Services write their own artifact files and then call `store.save` / `store.transition`. A LangGraph stage graph never changes run state and never writes `RunManifest.json` (`CONTRACTS.md#stage-graphs`).
- **One transition function.** `apply_transition` in `app/workflow/run.py` is the only code that changes `Run.state`. It returns a copy; a rejected transition leaves the original untouched.
- **Handlers hold no business logic.** `app/api/*.py` call services in `app/workflow/` and the stores. There is no public endpoint that moves a run to an arbitrary state.
- **The UI holds no business logic.** It shows what the API returns (state, `next_action`, open questions) and turns errors into messages.
- **Fail closed.** No auth bypass flag exists. Missing Entra settings give `500 CONFIG_ERROR` on every protected endpoint. A missing or invalid config file (`config/critical_terms.yaml`) stops the API at startup, naming the file.
- **Never read or print `.env`.** New settings are added to `.env.example` with empty values (`.env.example` and `rayfin-ui/.env.local.example` hold names only).
- **Never log tokens, secrets or Fabric/Entra error descriptions.** Log error codes only. Messages that go to the client never contain a token.
- **Task workflow:** `/implement-task T-xxx` (branch from `main`, implement, run the offline checks, update `.claude/MANUAL_TESTING.md` and `.claude/CLAUDE.md`, set the README status to `Awaiting manual test`); `/commit-push` (safety checks: no secrets, binaries or generated files; the repo is public); `/cleanup-branch` (delete a merged branch after confirmation). Live steps (browser, Entra, Fabric, Azure OpenAI through the API) are the developer's to run.

## 4. Setup shared by the manual steps

Do this once; the per-task sections refer to it as "the setup".

1. **Environment.** Windows, Python 3.12 virtualenv in `.venv` (`.venv\Scripts\activate`, `pip install -r requirements.txt`), a `.env` copied from `.env.example` with the Azure OpenAI and Fabric values filled in (never print it). `pip install -r requirements.txt` also installs `fastapi`, `uvicorn`, `httpx`, `PyJWT[crypto]`, `msal`, `langgraph>=1.0,<2` (all added during this session).
2. **Run store.** The default `RUN_STORE=file` needs nothing. For the SQL store set `RUN_STORE=fabric_sql`, `FABRIC_CONTROL_DB_SERVER` and `FABRIC_CONTROL_DB_NAME` to a **writable Fabric SQL Database** in the sandbox workspace (never the Lakehouse SQL endpoint, which is read-only), and install ODBC Driver 18 for SQL Server. The two stores are separate: runs made with one don't appear in the other.
3. **Entra (needed from T-105).** Two app registrations in the tenant (steps with portal clicks are in `.claude/MANUAL_TESTING.md`, section T-105):
   - `nexora-api`: Application ID URI `api://<api-client-id>`, scope `access_as_user`, a client secret, delegated permissions Power BI Service `Workspace.Read.All` + `Lakehouse.Read.All` (or `Item.Read.All`) and Azure Storage `user_impersonation`.
   - `rayfin-ui`: single-page application, redirect URI `http://localhost:3000`, delegated permission to `nexora-api`'s `access_as_user`.
   - `.env`: `ENTRA_TENANT_ID`, `ENTRA_API_CLIENT_ID`, `ENTRA_API_CLIENT_SECRET`. `rayfin-ui/.env.local`: `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`, `NEXT_PUBLIC_ENTRA_TENANT_ID`, `NEXT_PUBLIC_ENTRA_CLIENT_ID`, `NEXT_PUBLIC_API_SCOPE=api://<api-client-id>/access_as_user`. Restart the UI after editing `.env.local`.
4. **Start the API:** `uvicorn app.api.main:app --reload --port 8000` (Swagger at <http://localhost:8000/docs>). **Start the UI:** `cd rayfin-ui; npm install; npm run dev`, then open <http://localhost:3000> (it must be port 3000: the API's CORS allows only that origin).
5. **Get a token for Swagger or curl:** sign in to the UI, press F12, *Network*, click any request to `localhost:8000`, copy the part of the `Authorization` header after `Bearer `; in Swagger click **Authorize** and paste it, with curl use `-H "Authorization: Bearer <token>"`. It lasts about an hour; treat it like a password.
6. **Create a run without the UI:** `POST /runs` in Swagger with `{"prompt": "Show revenue by month for 2024"}`, copy the `run_id`.
7. **Clean up afterwards:** stop the API and the UI, restore any `.env` line you changed, delete test runs' folders under `runs\`.

The **offline checks** need none of this (no sign-in, no network, temporary folders, fakes for Fabric, the model and Entra): `python -m app.manual_tests.t101_offline_checks`, `t102_…`, `t103_…`, `t105_…`, `t201_…`, `t202_…`, and `cd rayfin-ui; npm test; npm run typecheck; npm run build` for the UI. `t103_connectors_check` is the only live script of the session (needs a browser sign-in). ## 5. T-101 Run model, state machine and run store

**Spec:** FR-001, FR-021, §11, NFR-003. **Depends on:** T-001.

### Steps taken
1. Read the spec's state model and the task. Asked which control store to use; the answer was both stores, with the SQL store configured from `.env` and acceptance criteria that don't need the live database.
2. Wrote `app/workflow/states.py`: the 15-state `RunState` enum, the `ALLOWED` table from `CONTRACTS.md`, and `can_transition(a, b, resume_state=None)`. `NEEDS_INPUT` is reachable from every state except `COMPLETED`; leaving it is decided by the run's `resume_state`. A state can't move to itself.

### How it works
- **`Run`** matches `CONTRACTS.md#run`: `schema_version`, `run_id` (UUID v4), `prompt`, `subject_area`, `desired_outputs`, `constraints`, `state`, `resume_state`, `scope`, `created_by`, `created_at`, `updated_at`, `history[]`, `artifacts{}`, `deployment`. Timestamps are UTC ISO 8601 with a `Z`.
- **`apply_transition(run, to, reason, actor="system")`** returns a deep copy. `to=None` is valid only from `NEEDS_INPUT` and means "go back to `resume_state`" (falling back to `CREATED`). Moving into `NEEDS_INPUT` stores the previous state as `resume_state`; leaving clears it. Every success appends `{from, to, at, reason, actor}`. A same-state move is illegal, so history never gets duplicates.
- **`FileRunStore(root=PROJECT_ROOT/"runs")`** writes `runs/<run_id>/RunManifest.json` through `RunManifest.json.tmp` and `os.replace` (atomic). `get` rejects anything that isn't a UUID (also blocks path tricks), raises `RunCorrupt` for an unreadable manifest; `list` skips corrupt runs with a warning, sorts newest first, applies `limit`.
- **`SqlRunStore(server, database, connect=None)`** keeps one row per run in `dbo.nexora_runs` (`run_id` PK, `state`, `created_at`, `updated_at`, `version`, `manifest` JSON). It creates the table on first use, commits or rolls back one transaction per call, and `transition` is optimistic: `UPDATE … WHERE run_id = ? AND version = ?`; if no row matched it re-reads and re-validates, up to 3 attempts, then `StoreUnavailable("…being changed by another writer…")`. A `pyodbc` failure is `StoreUnavailable`. The connection is `FabricSQLConnector(server, database).connect`, injectable for tests.
- **CLI exit codes:** `0` success, `1` domain error (`RunNotFound`, `IllegalTransition`, `RunCorrupt`, `StoreUnavailable`), `2` bad input (empty prompt, bad state name, bad `RUN_STORE`, missing `FABRIC_CONTROL_DB_*`). `transition` takes `STATE` or the keyword `RESUME`. Output is forced to UTF-8 (messages contain "→").

### Gotchas
- `RunStore.transition` and `save` are the only ways to persist a state change; nothing outside `app/store/` may write a manifest.
- The file store and the SQL store do not share runs. `GET /runs` reads whichever `RUN_STORE` selects.
- The SQL store needs a **writable** Fabric SQL Database. The Lakehouse SQL endpoint is read-only and would fail on the first `CREATE TABLE`.
- Later tasks added optional arguments to `create` (`created_by`, T-105) and many artifact files next to the manifest; the manifest format itself only grew new `artifacts` entries.

### Offline checks (`t101_offline_checks`)
The 15 states, a terminal `COMPLETED`, same-state and illegal transitions, prompt validation (empty and too long), the file store (manifest written, no `.tmp` left, unique ids, illegal transition leaves state and history, legal one recorded with its reason, `resume_state` stored and used, a new instance sees the same data, state filter, newest first, unknown and non-UUID ids, corrupt manifest in `get` and skipped in `list`, list on a missing folder) and the SQL store on the SQLite stand-in (DDL targets `nexora_runs`, create and get, `resume_state`, history, unknown id, state filter, corrupt row in `get` and skipped in `list`).

### How it works
- **Models** (all `extra="forbid"`): `BusinessContract` (`schema_version`, `run_id`, `version`, `status` draft|approved, `domain`, `business_objective`, `grain`, `entities`, `kpis`, `dimensions`, `filters`, `currency`, `exclusions`, `security`, `open_questions`, `locked_facts`, `assumptions`, `feasibility`), `Kpi` (name, `formula_intent`, `grain`, `filters`, `time_logic`, `exclusions`, `currency`, `expected_examples`, `status` draft|approved|data_gap, `rationale`), `OpenQuestion` (`id`, `text`, `blocking`, `reason`, `source` rule|llm|reviewer, `status` open|answered, `answer`), `LockedFact` (`id`, `text`, `source_question_id`, `locked_at` as text), `Feasibility` (the T-402 shape: `kpi`, `status`, `needed`, `missing`, `options`), `SecurityRequirement`, `ExpectedExample`.
- **Rules** (in a model validator, so building a contract in code enforces them too): KPI names unique ignoring case (the message names both entries); question ids and fact ids unique; a locked fact's `source_question_id` must name an existing question; with `status: approved` there must be no open blocking question and every KPI needs `formula_intent`, `grain` and `currency`. Violations are reported as `path: message` lines (`kpis.0.formula_intent: required when the contract is approved`).
- **Validation output** (`check`, `parse`, `load`): YAML syntax errors give `line N, column M: …`; an empty or comment-only file is `empty document`; an unknown field is `<path>: extra field not permitted`; a `schema_version` newer than 1 is `unsupported schema_version N`; a non-UTF-8 file is `INVALID`, not a crash. `ContractInvalid.issues` is the list of lines.
- **Saving** (`save(contract, path) -> "sha256:<hex>"`): `yaml.safe_dump` of `model_dump(mode="json")` in model field order, block style, UTF-8, LF, written as **bytes** through a `.tmp` file and an atomic replace, so Windows never writes CRLF. The hash is the SHA-256 of the file bytes (`content_hash`). Saving the same contract twice gives the same bytes and hash.
- **CLI:** `contract validate FILE` prints `VALID` (exit 0) or `INVALID` and one line per error (exit 1), exit 2 for a missing file; `contract schema` prints the JSON Schema, `--output FILE` writes it as UTF-8 with LF (PowerShell 5.1's `>` would write UTF-16, which is why the option exists).
- `open_blocking_questions(contract)` is the helper later tasks (G1, the compiler) use.

### Gotchas
- The contract hash is a hash of the **file bytes** in canonical order, not of a re-sorted dump as `CONTRACTS.md`'s general hash rule says; this is the hash stored in the manifest's `BusinessContract` artifact and used as `expected_hash` by later tasks. Don't hand-edit contract YAML and expect the same hash.
- After changing any model, regenerate `schemas/business_contract.schema.json` (`python -m app.cli contract schema --output schemas/business_contract.schema.json`); `t201_offline_checks` fails when the committed file is out of date.
- `samples/contract_valid.yaml` must stay in the `save()` format (block style); re-save it with `save()` rather than editing it by hand.
- A new field on the contract needs a default (so older files load), and must be added to the compile prompt/schema in T-202 if the model should fill it (see `_ROOT_EXCLUDED` and `_DEF_EXCLUDED` in `app/compiler/requirement_compiler.py`).

### How it works
- **Endpoint:** `POST /runs/{id}/compile` → `200 {"run": RunDetail, "contract": BusinessContract, "blocking_questions": int}`. Allowed in `CREATED` and `NEEDS_CLARIFICATION` only (`409 WRONG_STATE`, `details: {state, allowed}`).
- **`compile_run(store, runs_root, run_id, actor, llm=None)`**: checks the state → loads `runs/<id>/BusinessContract.yaml` as `previous` → `compile_requirement` → on `LlmInvalidOutput` writes `runs/<id>/logs/compile-<UTC timestamp>.json` with each attempt's raw output and errors, then re-raises → picks the next free version number → saves `contracts/BusinessContract.v<n>.yaml` and `BusinessContract.yaml` (same bytes) → registers the manifest artifact `BusinessContract` (`path`, `version`, `hash`, `status: draft`) with `store.save` → transitions: `NEEDS_CLARIFICATION` while a blocking question is open, `CREATED` otherwise; **a state that wouldn't change adds no history entry** (compiling a `CREATED` run with no blockers, or recompiling in `NEEDS_CLARIFICATION` with blockers, leaves history alone). The history actor is the caller's UPN.
- **The `compile` graph** (`llm_compile → validate_schema → (retry llm_compile with the errors) → apply_critical_terms → apply_locked_facts`): state is a `TypedDict` (`run`, `previous`, `attempt`, `errors`, `raw`, `attempts_log`, `draft`, `contract`). Routing after `validate_schema` uses only the validator result and the attempt count: valid → `apply_critical_terms`; invalid and `attempt < 2` → `llm_compile`; otherwise the graph ends with no contract and `compile_requirement` raises `LlmInvalidOutput` (`502 LLM_INVALID_OUTPUT`, state unchanged). Every path that produces a contract ends in `apply_critical_terms` then `apply_locked_facts`. The graph never touches the store or run state, has no checkpointer and no `interrupt()`.
- **`run_graph(graph, state, *, run_id, stage, recursion_limit=25)`** streams the graph (`stream_mode="updates"`), collects the node path, logs `stage=compile run_id=<id> node_path=llm_compile -> … -> apply_locked_facts` at INFO (visible in the uvicorn console: `main.py` switches on the `app` logger only) and converts `GraphRecursionError` into `GraphLoopError` (a bug, `500 INTERNAL_ERROR`).
- **What the model sees:** only the system prompt and `Business requirement`, `Subject area`, `Desired outputs`, `Constraints`, the previous contract as YAML and, on the retry, the validation errors. No source data (NFR-008). `config`/`previous` never carry rows.
- **The strict schema** (`llm_schema()`): T-201's JSON Schema with these fields removed because code sets them: `schema_version`, `run_id`, `version`, `status`, `locked_facts`, `feasibility` at the root, a KPI's `status`, and a question's `id`, `source`, `status`, `answer`; unused `$defs` are dropped; every remaining property is made `required` with `additionalProperties: false`, and keywords strict mode rejects (`default`, `title`, `minLength`, `maxLength`, `minimum`, `maximum`, `format`) are removed. The model's JSON is then validated again with T-201's full model (`parse_draft` → `check`), so a duplicate KPI name or an unknown field is a normal validation error and triggers the retry.
- **Code-set fields in `parse_draft`:** `run_id`, `version` (previous version + 1, else 1), `status: draft`; `domain` is the model's value, else the run's `subject_area`, else `Sales`; the model's questions get temporary ids `LLM-1…`, `source: llm`, `status: open`, `answer: null`; `entities` and `dimensions` get a capital first letter and are de-duplicated ignoring case (so "month" and "Month" don't change the structure between runs: NFR-009).
- **Ambiguity rules** (`app/compiler/critical_terms.py`, run after the model on every path):
  - `config/critical_terms.yaml` maps each business-critical term to aliases; a term (or alias) mentioned in the prompt or constraints as a whole word, ignoring case, that has **no definition** gets a blocking question `id: RULE-<TERM>` (for example `RULE-REVENUE`, `RULE-SAME-STORE-SALES`), text "How is `<Term>` defined?", `reason: Business-critical term without definition`, `source: rule`. A definition is one of `definition_patterns` with `{term}` filled by the term or an alias ("Net Revenue = …", "Revenue is defined as", "… means", "define revenue as"); whitespace is flexible and optional next to punctuation.
  - No KPI in the draft gives the blocking question `RULE-METRIC` "Which metric should be measured?".
  - A rule question that was already **answered** in the previous contract (or has a locked fact pointing at it) is not raised again.
  - The model can't remove or weaken a rule question: rule questions replace any model question with the same id; a model question that mentions a term a rule question already covers is dropped as a duplicate (this is why the model doesn't get "Revenue" asked twice).
  - `apply_locked_facts` carries the previous contract's answered questions and locked facts into the new contract unchanged, renumbers the model's questions `Q1, Q2, …` (skipping used ids), and drops a model question whose normalized text repeats another question's.
- **Startup check:** `app/api/main.py` loads `config/critical_terms.yaml` in the FastAPI lifespan; a missing or invalid file stops the API with a message naming the file (`ConfigError`; at request time the same error is `500 CONFIG_ERROR`).
- **Error mapping:** `WrongState` → `409 WRONG_STATE`; `LlmInvalidOutput` → `502 LLM_INVALID_OUTPUT` (message says the raw output is in the run's `logs` folder); `LlmTimeout` → `504 UPSTREAM_TIMEOUT`; `PromptRejected` → `422 PROMPT_REJECTED`; `LlmUpstreamError` → `502 UPSTREAM_ERROR`; `ConfigError` → `500 CONFIG_ERROR`.
- **`GET /runs/{id}`** now returns `open_questions`: the open questions of the current contract file as objects (`id`, `text`, `blocking`, `reason`, `source`, …); empty when there is no contract.

### Prompt tuning made after the first live model call (keep when editing the prompt)
- The model repeated the Revenue question in its own words, and marked a detail question ("What criteria define a cancelled order?") as blocking, which would have stopped a run whose Net Revenue is defined. Fixes: the system prompt says business-critical terms are checked by rules ("Don't ask what they mean"), blocking only when work can't proceed at all, never for details of a definition the requirement gives; the duplicate filter above.
- The model left `dimensions` empty for "by month"; the prompt now says dimensions include time periods.

### Gotchas
- **Contract files live in `runs/<id>/` for both run stores** (only the manifest is in the SQL store), so `get_runs_root()` returns `PROJECT_ROOT/"runs"`; tests override it and the store together.
- The model's determinism is limited (NFR-009): structure (KPI names, dimensions, question set) is made stable by the rules above; wording of `rationale` and `formula_intent` may differ between runs.
- If both attempts are invalid, nothing is written except the failure log.
- `langgraph` must be installed (`pip install -r requirements.txt`); the graph is built per call, with the model passed in (`build_compile_graph(llm=…)`), so tests inject a fake.
- Keep `app/graphs/*.py` free of `.transition(`, `.save(` and `RunManifest`; `t202_offline_checks` greps for them.
- The checks print an expected "Authentication is not configured" log line when the in-process API runs without Entra settings; that is the fail-closed behaviour.

## 14. Cross-cutting gotchas (Windows, git, tooling)

- **Run everything from the project root** and as modules (`python -m app.…`); imports are absolute.
- **Large scripts in a bash heredoc can fail** with "unexpected EOF"; write the script to a file (the Write tool) and run it.
- **PowerShell 5.1 `>` writes UTF-16.** Use a tool option that writes the file itself (`contract schema --output`), or `Out-File -Encoding utf8`.
- **Line endings:** git's `autocrlf` makes Windows working copies CRLF while the repo stores LF. Files that tests compare byte for byte or hash are pinned to LF by `.gitattributes`. When a pulled file is still CRLF after that, restore it: `git rm --cached -r -q samples schemas; git reset -q samples schemas; git checkout -- samples schemas`. Don't convert whole `.claude/*.md` files; the editing scripts of this session preserved each file's existing line endings.
- **A `.venv` copied from another machine** fails with "No Python at …"; recreate it with `py -3.12 -m venv .venv`.
- **Never kill processes by image name.** To free port 3000 or 8000 find the PID (`netstat -ano | findstr :3000`) and stop only that one.
- **`runs/` is gitignored** (`/runs/`, anchored); never commit a run folder. `config/` files are committed (read on every call where noted), so don't put real UPNs or secrets in them: the repository is public.
- **The SQL run store and the SQL endpoint are different things:** the run store needs a writable Fabric SQL Database; the profiler and relationship checks of later tasks read the Lakehouse SQL endpoint.
